# 영어 지원

한국어·영어를 한 서비스에서 함께 제공하기 위한 결정과 이유를 정리한다. 구현 방법은 [`web/src/libs/i18n/`](../web/src/libs/i18n/)를 직접 읽는다.

## 구조

**별도 서버·화면을 두지 않는다.** 계정·구독·읽기 기록과 API 서버는 공유한다. 고정 문구는 프론트엔드 번역 파일이, 운영자가 수정하는 소개·공지·푸시는 서버가 언어별로 책임진다. 서버가 반환한 소개문을 `t()`로 다시 번역하지 않는다.

## 범위

| 구분 | 대상 |
| --- | --- |
| 첫 적용 | 웹의 로그인 → 가입 → 뉴스레터 탐색·구독 → 수신·읽기 → 내 정보 |
| 한국어 유지 | 어드민 화면. 번역 콘텐츠 편집 기능만 추가 |
| 후속 | 블로그·이벤트·매일메일, 앱 자체 화면 |
| 보류 | 챌린지 ([아래](#챌린지)) |

지원하지 않는 화면에 영어 사용자가 들어오면 "이 화면은 한국어로만 제공됩니다" 안내를 띄운다. 브라우저 언어 감지 때문에 영어 사용자가 처음부터 영어로 들어오기 때문이다. 번역 키 누락 시 한국어 fallback은 개발 중에만 허용하고, 지원 화면의 누락은 배포 전에 막는다.

## 번역하지 않는 것

- **뉴스레터 원문, 메모, 댓글은 원문을 유지한다.** 자동 번역하지 않는다.
- 뉴스레터 이름·발행처는 고유명사로 둔다.
- **영어 화면이라고 한국어 뉴스레터를 숨기지 않는다.** `locale`(소개를 보여줄 언어)과 `contentLanguage`(원문 언어)는 다른 값이다. 영어 뉴스레터만 보여줄지는 미결정이다.

## 언어 결정

| 상황 | 규칙 |
| --- | --- |
| 비로그인 | 이 브라우저에서 직접 고른 값 → `navigator.languages` 중 첫 지원 언어 → `ko` |
| 로그인 | 계정의 `preferredLocale` 우선. 단, 로그인 직전에 직접 고른 값이 있으면 그 값을 계정에 저장 |
| 가입 | 가입 시 표시 중인 언어를 계정에 저장 |
| 서버 저장 실패 | 화면은 고른 언어를 유지하고 실패를 안내 |
| 로그아웃 | 계정에서 불러온 값은 지우고 직접 고른 값만 남김 |

- **로그인 시 계정 값을 우선한다.** 예전에 한 브라우저에 남긴 값이 다른 기기에서 나중에 고른 값을 덮어쓰지 않게 하기 위해서다.
- **기존 회원은 서버에서 `ko`로 채운다.** 비워 두면 OS를 영어로 쓰는 기존 한국어 사용자가 갑자기 영어 화면을 보게 된다.
- 번역 파일은 JSON이 아니라 `.ts`로 둔다. tsconfig를 바꾸지 않고 한국어 키 기준으로 영어 번역의 누락·초과 키를 타입 검사에서 잡기 위해서다.

## 챌린지

**영어 지원을 보류하고, 영어 화면에서는 진입점을 모두 숨긴다.** 데이터와 API는 그대로 두므로 한국어로 돌아오면 다시 보인다.

- 숨김 대상: 상단 메뉴, 메인 챌린지 섹션, 리더보드 챌린지 뱃지, 내 정보의 나의 챌린지 탭, 알림 설정의 챌린지 항목
- **메뉴만 숨기면 공유 링크·북마크·푸시로 들어오는 경로가 남는다.** 그래서 [챌린지 레이아웃 route](../web/src/routes/_bombom/_main/challenge.tsx)에서 홈으로 보낸다.
- 진행 중인 챌린지가 있는 사용자는 English로 바꾸기 전에 안내를 본다. 참여 기록은 유지된다.
- **영어 회원(`preferredLocale=en`)에게는 서버가 챌린지 푸시를 보내지 않는다.** 알림 설정 항목도 숨기기 때문에 사용자가 직접 끌 수 없다.
- 마감·출석의 시간대 기준은 챌린지 영어 지원을 다시 검토할 때 정한다.

## 서버 계약

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 회원 언어 | `GET/PATCH /members/me`, 가입 요청에 `preferredLocale: 'ko' \| 'en'` | 기기 간 설정 공유, 언어별 푸시·메일 발송 |
| 조회 언어 | 뉴스레터·공지·카테고리 조회에 `locale=ko\|en` **쿼리**. 생략하면 기존 한국어 응답 | 헤더보다 URL에 드러나야 query 캐시·CDN 캐시를 언어별로 나누기 쉽다. 구버전 클라이언트도 그대로 동작해야 한다 |
| 번역 누락 | **한 콘텐츠 안에서 언어를 섞지 않는다.** 영어 번역이 게시되지 않았으면 전체를 한국어로 반환하고 `resolvedLocale`로 알린다 | 화면에서 "한국어 원문" 안내를 붙이기 위해서다 |
| 오류 | 기존 `message`는 유지하고 `code`(필요하면 `params`)를 추가한다. 프론트엔드는 `code`로 문구를 고르고, 모르는 코드는 공통 안내로 처리한다 | 서버의 한국어 `message`를 영어 화면에 보여줄 수 없다 |
| 어드민 | 언어별 게시 상태. 한국어 원문을 수정하면 영어 번역을 "재검수 필요"로 표시하고, 기존 영어 게시본은 유지한다 | 의미가 바뀐 경우에는 운영자가 직접 내린다 |

- 언어별 응답의 `queryKey`에는 `locale`을 객체로 넣는다: `['newsletters', { locale }]`. `['newsletters', 'en']`처럼 넣으면 상세 키 `['newsletters', id]`와 같은 자리에 의미가 다른 값이 들어간다.
- 읽음·북마크처럼 언어와 무관한 데이터는 캐시를 공유한다.
- 공용 fetcher는 i18n을 직접 import하지 않고 오류 정보만 넘긴다.

## 공개와 롤백

- **언어 선택 UI와 브라우저 언어 감지는 `ENABLE_I18N` 플래그 하나로 켠다.** 끄면 저장값을 무시하고 한국어로 표시한다. 메뉴만 숨기면 이미 영어를 쓰던 사용자의 선택값이 남기 때문이다.
- 서버를 먼저 배포한다(새 필드와 선택적 `locale`). 그다음 OpenAPI 타입을 재생성하고, 새 계약을 쓰는 프론트엔드를 배포한다.
- 언어 동기화를 지원하지 않는 구버전 앱에는 영어 선택을 노출하지 않는다. 설치된 앱은 웹처럼 즉시 되돌릴 수 없다.

## 앱

- 앱 안에서는 **앱이 언어를 정해** WebView에 전달한다. 비로그인이면 앱 저장값 → 기기 언어 → `ko` 순이다. WebView의 localStorage는 언어 결정에 쓰지 않는다.
- 초기값은 `?lang=` 쿼리나 `injectedJavaScriptBeforeContentLoaded`로 넘긴다. 현재처럼 로드 후에 실행되는 `injectedJavaScript`를 쓰면 한국어로 렌더링했다가 영어로 다시 바뀐다.
- 푸시는 OS가 표시하므로 웹 번역으로 처리할 수 없다. 첫 버전은 계정 언어로 발송한다.

## 미결정

- 영어 화면에서 영어 뉴스레터만 따로 보여줄지(`contentLanguage` 필터)
- 영어 검색 유입용 `/en/...` 주소, `hreflang`, 사이트맵
- 기기마다 다른 언어로 푸시를 보낼지
- 읽기 기록·출석 집계의 시간대 기준(백엔드 확인 필요)
